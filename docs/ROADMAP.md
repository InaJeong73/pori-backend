# PORI 후속 개발 계획

아래는 2026-09-20 코드 검토에서 정리한 **미완료 개선 후보**입니다.

| 우선순위 | 개선할 내용 | 완료 판단 기준 |
| --- | --- | --- |
| 1 | Hikari 설정 바인딩 점검 | 현재 `spring.hikari`를 실제 설정 경로 `spring.datasource.hikari`와 대조하고 런타임 풀 값 검증 |
| 1 | 로컬 환경 재현 | Compose DB 주소·JWT 전달, 샘플 데이터 주입 범위를 분리하고 새 환경에서 기동 확인 |
| 2 | 평가 파이프라인 | 모의 평가와 실제 AI 연동을 인터페이스로 분리하고 timeout·실패·재시도 테스트 |
| 2 | 비동기 트랜잭션 | 등록 트랜잭션과 평가 시작 시점의 경합 재현, 커밋 이후 처리 보장 |
| 3 | 피드 조회 | 동일 fixture에서 쿼리 수·응답 내용·정렬·페이지 경계를 전후 비교 |
| 3 | 게임화 | 현재 점수·랭킹과 제안된 등급·피드백 경험치의 구현 범위 확정 |

## 작업 기록 형식

각 개선은 문제 → 재현 조건 → 선택 이유 → 코드 변경 → 검증 결과 순서로 남깁니다. 제안 단계에 완료 표시나 측정 수치를 넣지 않습니다.

## 기존 문서와의 차이

- 원본 README의 H2 로컬 기본값·`com.backbone`은 현재 서비스 코드와 달랐습니다. PostgreSQL과 `com.pori` 기준으로 안내를 교체했습니다.
- 기존 구현 현황 문서의 회원가입 `handle` 예시는 현재 `RegisterRequest.nickname`과 달라 수정했습니다.
- 현재 Hikari 설정의 경로 문제 때문에 파일에 설정값이 존재한다는 사실만으로 런타임 적용 완료를 단정하지 않습니다.
